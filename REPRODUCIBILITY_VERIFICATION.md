# Aggregate Reconstruction Verification

## Scope

On 2 November 2026, the released analysis scripts were rerun in isolated working directories against retained, integrity-checked analysis inputs. The regenerated aggregate CSVs were compared with the aggregate evidence released with this repository.

This exercise verifies reconstruction of the released machine-readable aggregate evidence. It is not a raw-data-to-results rerun and does not redistribute provider data, individual-level outputs, checkpoints, model caches, or other disclosure-sensitive artifacts.

reconstruct the retained aggregate evidence; it does not represent them as
byte-identical historical snapshots. The post-review script is a new,
hash-pinned analysis layer rather than a reconstruction of a missing historical
file.

## Comparison procedure

For every retained and regenerated aggregate CSV, verification checked:

- the expected file set;
- column order and names;
- row and column counts;
- exact equality of categorical values;
- numerical equality with an absolute tolerance of `1e-12`; and
- SHA-256 equality to identify byte-identical files.

Integrity sentinels generated by each current script were also required to report `passed`. Markdown records were compared after newline normalization where applicable. Figures were not used to establish byte identity.

## Post-review extension verification

On 4 November 2026, the post-review extension checked the SHA-256 digests of
155 retained authoritative source files before analysis. It then generated 11
aggregate CSVs and one protocol record without training, encoding, model
scoring, or new evaluation-candidate sampling. An independent read-only check
confirmed the recorded source hashes, all 12 output hashes, expected row
counts, finite required numeric fields, and the declared bootstrap designs. The
recorded runtime was 91.3676 seconds under Python 3.12.14.

The released integrity record is intentionally sanitized: it includes the
public output hashes and verification counts but not the internal inventory of
checkpoint and per-query input filenames. The excluded inputs remain necessary
for an authorized rerun. See
[`aggregate_results/post_review/POST_REVIEW_INTEGRITY_SUMMARY.json`](aggregate_results/post_review/POST_REVIEW_INTEGRITY_SUMMARY.json)
and [`protocols/post_review/STUDY_PROTOCOL.md`](protocols/post_review/STUDY_PROTOCOL.md).

## Interpretation and limits

The verification demonstrates that the current released analyzers reconstruct the released aggregate numerical evidence from the retained analysis inputs. It resolves the numerical aggregate-provenance concern created by the missing historical analyzer snapshots.

It does not demonstrate an end-to-end rebuild from provider data, make the current analyzers byte-identical to the missing historical versions, or alter the data-access and computational boundaries described in [DATA.md](DATA.md) and [REPRODUCIBILITY.md](REPRODUCIBILITY.md).
